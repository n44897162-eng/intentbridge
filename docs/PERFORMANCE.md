# 性能报告

预算来自任务书 §11。测量环境为 4 vCPU/3.6 GiB；数字是实测，不包含外部目标应用自身响应。

| 指标                         | 预算                       | 实测                                                        | 结论              |
| ---------------------------- | -------------------------- | ----------------------------------------------------------- | ----------------- |
| 已定位点击的引擎规划开销 P95 | <100 ms                    | **1.45 ms**（40 样本，真实 Chrome 流程）                    | 通过              |
| 编辑器打开 1000 步流程       | <2 s                       | **182 ms**（多次运行 139–246 ms）                           | 通过              |
| 单流程步骤上限               | 1000（Schema）/100（运行） | 未变化                                                      | 通过（刻意限制）  |
| 单流程文件上限               | 1 MB                       | 服务端请求体 2 MB、IR 步骤上限 1000；未做 10MB 包浏览器测试 | 部分 NOT_RUN      |
| Web 黄金流程总耗时           | 无硬指标                   | 约 650–740 ms（含浏览器导航/输入/等待后置条件）             | 记录              |
| Rust 500 次长跑              | 无持续内存增长             | RSS +20 KiB / 500 次                                        | 通过（虚拟源）    |
| Web 30 次长跑                | 无持续内存增长             | live heap 62.2→60.6 MiB；RSS 预留页增长                     | 通过（heap 口径） |
| 事件写入                     | 不阻塞 UI                  | 每事件一次 SQLite 插入（WAL），管理端轮询                   | 记录              |
| 证据过期                     | 默认 7 天                  | 启动/每次运行后清理；测试覆盖 API                           | 通过              |
| 2 小时连续运行               | 无未处理异常               | 未执行                                                      | NOT_RUN           |
| 10 MB 流程包 UI              | 不卡死                     | 未执行                                                      | NOT_RUN           |

## 解释

- WASM 编译是主要固定成本；Runner/扩展/管理端已改为编译一次、按运行实例化。
- 对话式事件与证据全部本地，无网络等待。
- 规划开销只测 `engine.submit` 的 WASM 调用，不含浏览器动作；符合“引擎内部规划开销”的定义。
- 真实浏览器的总耗时包含夹具的 120ms/1800ms 异步延迟，属于被测应用本身。
